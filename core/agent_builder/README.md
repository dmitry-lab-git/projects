# Agent Builder Core (`agent_builder`)

Локальный оркестратор контекстных окон и генерации модулей поверх `api_manager` и PostgreSQL.

## Назначение
Модуль превращает `core` из набора изолированных конвейеров в единую агентскую платформу. Вместо интеграции тяжелых внешних фреймворков (`LangGraph`, `CrewAI`) система использует собственные **агенты-строители (Builder Agents)**, которые опираются на актуальные слепки схем БД (`~/Projects/db/`), версионирование (`development.versions` / `version_updates`) и единый реестр фоновых процессов (`audit.workers_registry`).

---

## Планируемая структура пакета

* `__init__.py` — Инициализация пакета.
* `README.md` — Архитектурная спецификация и дорожная карта.
* `context_store.py` — Управление UUID-сессиями и историей окон в PostgreSQL (схема `agents`).
* `tools.py` — Песочница инструментов (чтение DDL, запись черновиков, READ ONLY SQL, `py_compile`).
* `prompts.py` — Системные контракты ролей (Архитектор, Строитель, QA-инспектор).
* `runner.py` — Цикл рассуждений (ReAct / Tool-calling) поверх `api_manager`.
* `blueprints/` — Шаблоны контрактов для новых воркеров (`worker_tracker`, SQL-миграции).
* `sandboxes/` — Изолированная зона сборки и проверки новых модулей до переноса в прод.

## Перспективы развития (Roadmap)

### Этап 1. Персистентная память контекстных окон (`schema: agents`)
* **Таблицы `agents.sessions` и `agents.messages`:** хранение истории диалогов, системных промптов, вызовов инструментов (`tool_calls`) и биллинга токенов с привязкой к `UUID`.
* **Сжатие контекста (Context Compaction):** автоматическая суммаризация длинных сессий для соблюдения лимитов окна и экономии бюджета.
* **Переиспользование мультимодального кэша:** интеграция с `processing.api_request_blobs_cache` для работы с тяжелыми PDF и сканами без повторной отправки.

### Этап 2. Конвейер Агентов-строителей (Self-Building Pipeline)
* **Агент-Архитектор:** анализ задачи пользователя на основе актуальных DDL-дампов (`db_dump.sh`) и графа знаний (`kernel.nodes` / `kernel.edges`).
* **Агент-Строитель:** генерация готовых `.py` и `.sh` модулей со встроенной телеметрией (`worker_tracker.py`) и маршрутизацией через `api_manager`.
* **Агент-Инспектор (QA):** автоматическая проверка синтаксиса (`py_compile`), прогон тестовых транзакций с `ROLLBACK` и подготовка записи для `development.version_updates` (`UVR`).

### Этап 3. Прикладные цифровые сотрудники
* **Дежурный SRE-инженер:** автоматический триггер при статусе `ALERT_FAILED` в `reports.v_workers_health` — чтение логов из `core/logs/`, диагностика причины и подготовка патча.
* **Аналитик `Ledger` и `Household`:** естественный язык запросов в интерфейсе Reflex PWA с безопасным формированием `SELECT`-отчетов по представлениям `reports.*`.
* **Мультиагентные цепочки:** сквозная обработка документов (`doc_ingress_hub` -> классификация -> сверка с `staging_transactions` и баланс-снимками -> аудит).
